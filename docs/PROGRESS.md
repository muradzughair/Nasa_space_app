## Decisions and assumptions (chronological)

1. **Data blocked.** The build sandbox network policy returns HTTP 403 for imbrium.mit.edu, pds-geosciences.wustl.edu, www.ncei.noaa.gov, copernicus S3 and AppEEARS (checked 2026-11-08, from both the cloud shell and the shell on the user's computer). npm and PyPI work. The user chose "build now with demo data". All data below is therefore **synthetic demo data** except the Earth land shape (real, from the PyPI package global-land-mask). Logged in data/manifest.md.
2. **Demo replaces readers only.** Trait extraction, z-scoring, scoring and hotspot merging are the same code for demo and real data. Real readers (PDS3 LOLA, PDS4 MOLA, GeoTIFF ETOPO) are implemented and tested only against synthetic files in the right formats (pipeline/test_readers.py), not against real NASA files.
3. **Mid-latitude Moon preset = Apollo 11 (Mare Tranquillitatis)** (user's choice).
4. **Traits (9):** relief, median slope, p90 slope, roughness (terrain, measured when DEMs exist); mean temperature, temperature range, soil/rock competence, dust cover (placeholders until MODIS/Diviner/THEMIS/geology are available); sun elevation (illumination; weighted only for the polar target).
5. **Common scale:** all bodies use about 2 km pixels in 28x28-pixel windows (one 0.5 degree Earth cell). Targets use the median of the 3x3 neighbouring windows. Mars MOLA (3.7 km) is upsampled to about 2 km before extraction.
6. **Score:** weighted RMS distance of z-scores, score = 100 * exp(-0.5 * d^2). z is computed against the Earth land distribution (log1p for relief, slopes and roughness), clipped to +-4.
7. **Hotspots:** greedy peak picking, at least 7 degrees apart, each merged with connected neighbours scoring at least 85 percent of the peak. 20 per target and purpose; 15 get a precomputed terrain patch.
8. **Patches are synthetic stand-ins** in demo mode (129 x 129 samples, 2 km, about 15.6 m). Slope statistics follow the traits; fine roughness is synthetic and labelled. When real Copernicus GLO-30 windows are available they must replace these (not implemented, needs network).
9. **Serving:** the app reads ../data/processed and ../assets, so serve the project root (not only /app). Needs a local static server because browsers block fetch() from file://.
10. **Rover figures:** Perseverance wheel radius, wheelbase and track measured from the supplied GLB; mass, max speed and VIPER-class lunar figures are from memory of public NASA descriptions and are marked verified:false in assets/models/rover_params.json (could not be checked, no network access to NASA).
11. **GLB:** compressed 11.7 MB to 2.85 MB (meshopt, 512 px textures, dedup/weld/prune/quantize) with a Node script; gltf-transform CLI could not be used because sharp's binary download failed. Model is already in metres, +Y up, forward +Z, ground at y=0; wheels are one fused mesh so the rover is treated as a rigid body.
12. **AI explanations:** no /.env found, so the cache uses template sentences. The optional language-model path (ANTHROPIC_API_KEY in .env, env var TERRA_LLM_MODEL) is implemented but untested.
13. **Bug fixed:** roughness had an edge-padding bias (31 m on a perfect plane); fixed by using only interior pixels; covered by test_readers.py.

## Known limits

- Validation of Atacama / Haughton / Death Valley ranks is **not meaningful on demo data** (validate.py says so). Run it again on real data.
- Polar target on real data needs a polar-stereographic LOLA product; the 16 pixel/degree cylindrical grid is distorted near the pole (see HANDOFF).

A speed governor brakes the motors when the rover is above the commanded speed (throttle x max speed) so it does not run away downhill. Power = mechanical power / efficiency + base power; energy in Wh, energy per metre as a rolling average over the last about 20 m of drive energy, battery bar from an energy budget, empty battery stops the rover.
